联网对战补充（2026-10-26）：
先重新运行 python -m pip install -r requirements.txt，安装新增联网依赖。
主界面“联网对战”内可选择局域网建房、局域网加入或在线房间。
局域网：房主创建后，把IP地址、端口和房间码发给同一局域网内的对手；双方点击准备后开始。默认TCP端口8765，需要防火墙允许当前局域网访问。房主需保持游戏运行。
在线：双方填入同一房间服务地址，一方创建房间，另一方用房间码加入。服务端需另行部署，详见server/README.md；没有默认公共服务器。
当前为不限时友谊局，支持双方准备、认输、棋谱导出和60秒内手动重连。关闭房间面板不会离开房间；“离开”会结束本方对局，房主离开局域网会关闭服务。重启客户端会丢失内存中的重连凭证。
房间规则：棋子耗尽或无合法走法判负；完整局面含行棋方三次重复、连续80手未吃子判和。对局结果由房主/独立服务端确认，房间规则不作为赛事认证。

以下为原本地人机候选版比赛操作说明：
苏拉卡尔塔棋：论文策略试验版（2026-10-24）

本项目包含论文候选引擎、Pygame界面、局域网/在线房间、资源和运行配置；tests与.github目录用于开发验证。
Python 3.10或以上；首次安装依赖：python -m pip install -r requirements.txt
解压后双击 run_game.bat。启动脚本关闭字节码缓存，避免生成__pycache__。

赛前：
1. 按要求准备腾讯会议共享屏幕、稳定网络和外部录屏。本程序不录制会议、不自动上传或发群消息。
2. 用记事本填写根目录“比赛信息.json”：组别、轮次、第几局、黑红方队名；每局开始前更新，第二局对调颜色和队名。
3. 程序黑方先手，请和对手确认坐标方向。自己执黑：黑方选AI、红方选人类；执红则反过来。根据对手共享屏幕把对手着法录入本地棋盘，不要开启双方AI代替远程对手。
4. 开局前在“设置”调整AI总思考时长，支持关闭或1至120分钟，按+/-逐分钟调整。旧默认15分钟不等于已确认的比赛限时。对局中锁定设置，避免重置内部时钟；下一局前再调整。

棋谱：
点击“开始”后，每次有效落子都会保存。路径是本程序目录下：棋谱/对局ID/
本局TXT、JSON和“逐步备份.jsonl”会持续更新；每局目录唯一，不覆盖上一局。
每局结束点击“导出棋谱”或按Ctrl+S，生成新的带“导出”文件名的TXT和JSON，不覆盖之前导出；把TXT发到组内，JSON和备份留作核对。
未到程序终局也能导出，例如对方认输、协商和棋、争议暂停；此时程序不擅自写获胜，最终结果按双方/助裁确认后另行报分。
重来/退出也会保存，但必须留意状态区是否显示保存失败。自动记谱不能代替录屏；文件系统或设备故障仍需人工备份。
正常运行产生的“棋谱”文件是正式对局资料，不是测试文件。联网测试使用临时目录，不生成正式棋谱。

两局结束后向助裁报分并双方确认，附两局棋谱；按组委会要求主动联系对手、发布会议号。
限时是单步/每方整局/整场两局，以及断线、暂停、调整生效局次，尚需助裁明确。界面用时是本地回合时间，AI余额只扣搜索时间，不能直接作为未确认的裁判计时口径。
本包默认paper_2022/depth5/5000ms，并启用前三回合安全环线排序。两项均为论文启发的候选功能，尚未通过正式比赛预算的棋力确认。程序由团队与Codex辅助开发，请依赛项要求如实说明。

论文策略说明：
来源：李东轩、胡伟、王静文，《基于Alpha-Beta算法的苏拉卡尔塔棋博弈系统研究》，2022年第12卷第2期123至125页。
开局前三次己方AI回合优先搜索疏通环线的安全走法，不强制走子，仍用搜索决定。存在立即吃子回复的安静走法不获得该战略奖励。
论文关键点位置表乘2后与原位置表各占50%；缩放和混合比例是本项目试验值，论文没有给定最优比例。
设置里的“论文试验”控制位置估值；切回其他估值时，开局排序仍按启动配置启用。若需完整关闭开局排序，手动以SURAKARTA_PAPER_OPENING_ORDERING=0启动main.py。
